### [x] M88 — Import Access form/report designs into sidecar designs (migration tool; SaveAsText or Access-free route) — 🟢
- **Location:** a new migration/import path (core or a tool crate), the sidecar schema (`SchemaDocument` forms/reports), `tools/fixture-build` as the SaveAsText precedent.
- **Problem:** Native Access form/report definitions are proprietary OLE-compound streams (`MSysAccessObjects`/`MSysAccessStorage`) with no official Microsoft specification, so DataCraft does not decode them directly. Access's own `SaveAsText` export writes readable text that Rust can parse into sidecar designs — recreating the forms approximately, not byte-identically.
- **Finding (2026-11-14) — an Access-free route exists:** `jetdb` (pure Rust, MIT OR Apache-2.0, v0.4.0; <https://jetdb.dominion525.com>, <https://github.com/dominion525/jetdb>) reads form/report designs — sections, controls and their properties — directly from Jet4/ACE `.mdb`/`.accdb`, with no Access install and no FFI. Its public `docs/form-design.md` documents the property-ID and control-type tables (e.g. `Caption` 0x0011, `ControlSource` 0x001B, `Left` 0x0036, `Top` 0x008D, `Width` 0x0096, `Height` 0x002C; TextBox 0x126D, ComboBox 0x136F, CheckBox 0x066A, CommandButton 0x0B68, SubReport 0x1B70) and states they were checked against Access's own SaveAsText output. Limitations: Access 97 (Jet3) form/report designs are not read; property IDs above 0x01C4 are left unnamed (Access for Microsoft 365 shifts them by one); unknown IDs surface as `0xXXXX`. The free Access *Runtime* is **not** an export substitute — design views and the VBA editor are removed/disabled in runtime mode. The SaveAsText grammar is documented by Microsoft only as an API method; public parsers exist (`accdt` crate, MIT/Apache-2.0; Project Copperfin), and the committed fixture exports remain our ground truth.
- **Decision (2026-11-14, ADR-9 in `docs/ARCHITECTURE.md` §18): Route B.** A separate migration tool (`datacraft-import`) links `jetdb` 0.4 and maps the supported subset into sidecar designs; the engine stays clean-room, the tool carries the third-party knowledge openly (`THIRD-PARTY-NOTICES.md`, README). Route A — our own decoder with jetdb as a test-time oracle — is fully specified as the fallback in `docs/ROADMAP.md` §20, including the generated-fixture recipe, table derivation, parity contract and effort.
- **Caveat:** The Access path still assumes the user can export via `SaveAsText`; the finding above removes that prerequisite for the no-Access route. The committed fixture exports make the text format a usable ground truth for the binary decoder (M89).
- **Approach:** a clean-room parser for the SaveAsText text format (Begin/End blocks, property lines) mapping the supported control subset (label, text box, check box, combo, command button, subform) with rect/caption/source properties into `FormDef`/`ReportDef` sidecar documents. Unsupported properties/controls are collected per object into a precise list, never silently dropped. The export step runs in Access/COM only at migration time (never in the product, AGENTS §6); the parser and import are pure Rust commands/tools. Events/VBA stay unbound (ADR-2). Depending on the decision above, the binary route reads the same subset through jetdb (as an oracle or as a linked adapter).
- **Acceptance:** an exported (or `jetdb`-read) sample form imports into a sidecar design whose runtime renders the supported controls at their rects; the unsupported list is precise; a fixture pair (source + expected sidecar) pins the mapping; no COM/unsafe path in the shipped code; the no-Access route is exercised once on the committed fixture.
- **Steps:** 77.1 (jetdb feasibility against the committed fixture) + 77.2 (route decision, High gate) + 77.3 (subset and fixture pair) — phase 77, packaged 2026-11-14, decision ADR-9. Implementation: 78.1–78.4 (`datacraft-import`, Route B), released 2026-11-14.
- **Done:** done in phase 77/78 (77.1 evidence e9c5a1a; 78.1 28f4ca9, 78.2 4d07763, 78.3 0d6252b, 78.4 c01a352 + phase close b7f6b00) — Route B via jetdb 0.4: datacraft-import imports the six supported control kinds into the sidecar without Access, reports unsupported controls/properties, writes only the sidecar; the generated six-kind/defaults fixture and exact expected sidecars pin the mapping; Access 97 designs, combo row sources and default-geometry controls are documented first-cut limits; Route A remains the fully specified fallback in ROADMAP §20
